# Настоящая регистрация игроков и клубов

Сейчас вход демонстрационный: аккаунты захардкожены, сессия хранится в браузере. Переводим регистрацию на реальный бэкенд (Lovable Cloud) с письмами-подтверждениями и модерацией клубов суперадмином.

## Как это будет работать

### Игрок
1. На странице `/auth` вкладка «Регистрация»: имя, город, телефон, email, пароль.
2. Система отправляет письмо со ссылкой подтверждения.
3. Экран «Проверьте почту» с подсказкой и кнопкой «Отправить письмо повторно».
4. По клику на ссылку — возврат в приложение, аккаунт активен, вход выполнен, роль `player`.
5. Без подтверждения вход невозможен — показываем понятную ошибку и кнопку повторной отправки.

### Владелец клуба
1. Отдельная вкладка «Зарегистрировать клуб»: контакт владельца (имя, email, телефон, пароль) + данные клуба (название, город, адрес, телефон, часы работы, число мест, цена за час, описание).
2. Такое же письмо-подтверждение почты.
3. После подтверждения владелец входит в кабинет, но видит статус «Заявка на модерации»: клуб не показывается игрокам и на карте, редактировать можно только карточку клуба.
4. Суперадмин во вкладке «Заявки» видит новую заявку с контактами, нажимает «Одобрить» или «Отклонить» (с причиной).
5. После одобрения клуб становится активным, появляется на карте, владельцу открывается полный кабинет. При отклонении владелец видит причину и может отредактировать и подать повторно.

### Суперадмин и админ клуба
- Суперадмин создаётся заранее (сид) — самостоятельно зарегистрироваться на эту роль нельзя.
- Админов клуба (`clubAdmin`) заводит владелец в своём кабинете: указывает email — приходит приглашение, после подтверждения аккаунт привязан к клубу.

### Про «почту внутри системы»
Внутренних почтовых ящиков не делаем: письма уходят на обычную почту пользователя. Подтверждение регистрации отправляет встроенный почтовый сервис Lovable Cloud (для брендированных писем позже можно подключить свой домен-отправитель).

## Техническая часть

1. Включаю Lovable Cloud (база + auth + письма).
2. Миграция:
   - `profiles` (id → auth.users, name, phone, city, created_at) + триггер автосоздания при регистрации;
   - `user_roles` (отдельная таблица + enum `app_role`: player, club_admin, owner, admin) и security-definer функция `has_role`;
   - `clubs` — перенос текущих полей из мока (name, city, address, phone, lat, lng, open_from, open_to, price_per_hour, total_seats, specs, description, cover, owner_id, status, applied_at, rejection_reason);
   - RLS: игрокам/гостям видны только клубы со статусом `active`, владельцу — свои в любом статусе, суперадмину — все; GRANT-ы для anon/authenticated/service_role;
   - сид: демо-суперадмин + текущие 4 активных клуба Astana.
3. Аутентификация: `supabase.auth.signUp` с `emailRedirectTo`, экран ожидания подтверждения, повторная отправка, `onAuthStateChange` в `__root.tsx`, гейт `_authenticated/`.
4. Регистрация клуба — server function: создаёт клуб со статусом `pending`, привязывает `owner_id` и роль `owner`.
5. Модерация — server function с проверкой роли `admin`: `approve` / `reject(reason)`.
6. `src/lib/auth.tsx` переводится на реальную сессию, демо-кнопки быстрого входа остаются только для тестовых аккаунтов (создам их реальными и подтверждёнными).
7. Бронирования, абонементы и отзывы на этом шаге остаются на текущем моке — переносим их в базу отдельным шагом, чтобы не ломать работающие экраны.
8. Все новые тексты добавляются в RU / KK / EN.

## Что не входит

- Перенос бронирований, абонементов и платежей в базу (следующий этап).
- Брендированные письма с собственного домена.
- Вход через Google/Apple.
