# Оплата абонементов через Kaspi с ручной проверкой

Сейчас покупка абонемента симулируется: игрок нажимает «Купить», часы начисляются сразу. Меняем на схему «перевод на Kaspi → игрок вводит номер квитанции → суперадмин подтверждает → часы начисляются».

## 1. Экран оплаты для игрока

- На странице абонементов кнопка покупки открывает модалку «Перевод Kaspi»:
  - реквизиты суперадмина (номер карты / телефон Kaspi) с кнопкой «Скопировать»;
  - сумма выбранного пакета (11ч / 19ч / 27ч / Безлимит);
  - обязательное поле **«Номер квитанции Kaspi»**;
  - кнопка **«Я перевёл деньги»**.
- После отправки: заявка со статусом «на проверке», часы пока не начисляются.
- В профиле и на странице абонементов игрок видит статус своей заявки: на проверке / подтверждена / отклонена (с возможностью отправить новую).

## 2. Данные

Таблица платежей расширяется полями: пакет (plan_id), номер квитанции, статус `pending` / `approved` / `rejected`, кто и когда проверил, причина отказа. Существующая логика статуса `succeeded` переводится на новую схему.

Права доступа: игрок создаёт и видит только свои заявки; суперадмин видит все и меняет статус. Игрок не может сам менять статус.

## 3. Панель суперадмина — вкладка «Проверка оплат»

- Таблица заявок со статусом «на проверке»: имя игрока, телефон, пакет, сумма, номер квитанции, дата.
- Кнопки **«Подтвердить и начислить часы»** и **«Отклонить»** (с причиной).
- Подтверждение: статус → `approved`, предыдущий активный абонемент игрока закрывается, создаётся новый на 30 дней с часами пакета (или безлимит). Всё одной защищённой операцией на сервере.
- Отдельно — список уже обработанных заявок (история).

## Техническая часть

- Миграция: `ALTER TABLE public.payments` — добавить `plan_id text`, `receipt_number text`, `reviewed_by uuid`, `reviewed_at timestamptz`, `rejection_reason text`; статус по умолчанию `pending`; политика UPDATE только для `has_role(auth.uid(),'admin')`, INSERT — только свои строки со статусом `pending` (защитный триггер, чтобы игрок не проставил `approved`).
- Новый файл `src/lib/payments.functions.ts`: `submitKaspiPayment` (авторизованная, создаёт заявку), `approvePayment` / `rejectPayment` (`requireSupabaseAuth` + проверка роли `admin`, начисление абонемента через `supabaseAdmin`, импорт внутри handler).
- `src/lib/store.tsx`: `buySubscription` заменяется на `submitKaspiPayment`; добавляются `pendingPaymentFor(userId)` и перезагрузка платежей.
- `src/components/PaymentDialog.tsx` переделывается под Kaspi-реквизиты и поле квитанции (остальные способы оплаты убираются с экрана абонементов).
- `src/routes/admin.tsx`: новая вкладка «Проверка оплат» + связка с профилями (имя, телефон).
- `src/lib/i18n.tsx`: русские строки нового флоу.

## Что нужно от вас

Укажите реквизиты Kaspi для приёма переводов: номер телефона и/или номер карты и имя получателя — впишу их в модалку. Если хотите менять их без правок кода, сделаю поле в панели суперадмина.
